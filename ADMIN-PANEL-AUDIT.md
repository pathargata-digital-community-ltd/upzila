## নিরাপত্তা ও deployment নোট

- `database.rules.json`-এর বর্তমান Native-App version-এ `area_access_requests/{uid}`-এর applicant/admin authorization এবং `blood_partner_access_requests`/`blood_partner_access`-এর admin-only management rules আছে। Native App submit flow-তে profile-এর protected gate fields client থেকে পরিবর্তন হয় না—শুধু নিজের NID URL ও request queue atomicভাবে লেখা হয়।
- ব্যবহারকারী Firebase Console-এ Rules ম্যানুয়ালি আপডেট করেছেন বলে জানিয়েছেন। লাইভ Firebase Rules এই repository-র tested version-এর সঙ্গে মেলে কি না Console-এ যাচাই করতে হবে; Rules deploy ও GitHub Pages code deploy আলাদা অপারেশন।
- Panel-এর ১৯টি navigation target-এর প্রতিটির matching tab আছে; বাদ দেওয়া UI থেকে কোনো Firebase data bulk-delete করা হয়নি।
- Cloudinary upload client-এর unsigned preset ব্যবহার করে; trusted server-side delete/destroy endpoint app বা panel source-এ পাওয়া যায়নি। তাই trashed post-এর Cloudinary file auto-delete হবে না।
- Native app source-এ OneSignal integration পাওয়া যায়নি; deleted panel handler key revoke/rotate করেনি। Cloudinary deletion endpoint বা OneSignal key rotation হয়নি—এগুলো আলাদা server/account-side কাজ।
- Blood operator application UI indexed `status='pending'` query ব্যবহার করে; এটি অপেক্ষমাণ আবেদন ছাড়া approved/rejected records বা তাদের ব্যক্তিগত contact details fetch করে না। প্রতিটি submission-এর `revisionId` আলাদা; Admin action displayed revision-এর সঙ্গে বর্তমান record মিলিয়ে transaction lock নেয়, তাই stale card নতুন resubmission-এ কাজ করতে পারে না। পুরোনো pending entry-কে প্রথম owner lock `legacy:{requestedAt}` revision দিয়ে migrate করে। Lock থাকলে বিপরীত সিদ্ধান্ত নিষ্ক্রিয়, একই সিদ্ধান্ত retry/resume করা যায়। Approval-এ membership, final request status এবং actor/time-সহ audit event এক atomic multi-location update; rejection-এ status/audit atomicভাবে লেখা হয়।
- SOS Rules সাধারণ sensitive aliases (`phone`, `phoneNumber`, `requesterName`, `email`, `gps`, `coordinates` ইত্যাদি) public projection-এ deny করে; বিদ্যমান alert update-এ Admin claim-এর সঙ্গে `updatedAt`/`updatedBy` বাধ্যতামূলক এবং alert delete নিষিদ্ধ। অনুমোদিত status: `reported → responding/resolved/cancelled`, `responding → reported/resolved/cancelled`, `resolved → responding/cancelled`, `cancelled → reported`। Panel alert change ও `super_admin_audit` event atomicভাবে লেখে। RTDB Rules sibling audit event-এর অস্তিত্ব আলাদা করে enforce করতে পারে না—তাই direct/custom SDK moderation নয়, Admin Panel ব্যবহার করতে হবে। Live Rules-এ এই repository version/merge না থাকলে UI নিরাপদ error দেখাবে।
- Firebase rules file ও panel source repo-তে থাকা পরিবর্তন; GitHub Pages push এবং Firebase live rules deployment আলাদা অপারেশন। Live Rules-এ একই admin-claim policy কার্যকর কি না Firebase Console-এ যাচাই করতে হবে।
- Local Firebase RTDB emulator test: সর্বশেষ যাচাইয়ে ২৩টি test file-এর ১৪৩টি test পাস করেছে, blood partner owner/admin, SOS Admin triage/audit এবং community submission Rules tests-সহ।
- Native SOS screen-এ `resolved`, `cancelled` ও `rejected` alert active list থেকে বাদ; in-progress alert live status হিসেবে দেখা যায়। `/service/emergency` এখন canonical `/emergency` SOS form-এ redirect করে—আগের `service_requests/emergency` path-এর unruled submission/listener আর ব্যবহার হয় না।
- Push notification/OS-level Admin alert এই implementation-এ যোগ হয়নি; real-time queue দেখতে Admin Panel খোলা থাকতে হবে। জীবনঝুঁকিতে app-এর ৯৯৯ direct-call flow-ই ব্যবহার করতে হবে; Admin portal সরকারি dispatch system নয়।
- Native App TypeScript check (`pnpm run check`) সফল হয়েছে।
- Sidebar → **পর্যটন/পরিবহন আবেদন**-এ তিনটি real-time, আলাদা queue আছে: Tourism contribution, Transport provider application এবং generic transport request। প্রতি তালিকায় pending count, row status/date, user-submitted contact/details, permission error ও retry control দেখা যায়।
- Suggestion approve করলে curated `/services/data/history_tourism/community-{requestId}` record; correction approve করলে existing `placeId` record; review approve করলে `approvedReviews`, `reviewCount`, `averageRating`; report approval হলে শুধু resolved status লেখা হয়—নতুন place বানানো হয় না। Reject করলে public catalog-এ কিছু যায় না।
- Provider approval কেবল allowlisted type (`rent_a_car`, `cng`, `auto_rickshaw`, `motorcycle`, `bus`) গ্রহণ করে এবং matching `/transport/{type}/provider-{requestId}` record তৈরি করে। এই অনুমোদনের পর phone/WhatsApp/service area user-visible হয়। Generic transport request শুধু resolved/rejected হয়; provider directory-তে promote হয় না।
- Review action বর্তমান Admin custom claim আবার refresh করে যাচাই করে; request fresh-read করে pending state মিলিয়ে তারপর status, public record update এবং immutable `super_admin_audit` event একই multi-location update-এ লেখে। Rules ছাড়া Admin UI authorization boundary নয়।
- `database.rules.json`-এ Tourism/provider queue Admin-only read, transport request Admin-only read, user-owned pending submission validation, Admin pending-only সিদ্ধান্ত এবং public destination write restrictions যোগ হয়েছে। সম্পূর্ণ rules document Firebase production-এ আলাদাভাবে backup/review/deploy করতে হবে; GitHub push Rules publish করে না।
- Native Rules emulator suite সর্বশেষ run-এ ২৩টি test file, ১৪৩টি test পাস করেছে; TypeScript check পাস।
- Lock screen-এর Admin Contact: বিদ্যমান WhatsApp link অক্ষত রেখে Settings-এ Telegram link যোগ করা হয়েছে; Native App কেবল অনুমোদিত domain-এর HTTPS link-ই খোলে।

- Verification screen-এ ৬টি ক্যাটাগরির আলাদা রঙ, আইকন, depth/shadow-সহ 3D-স্টাইল badge preview যোগ হয়েছে: পাবলিক ফিগার, কন্টেন্ট ক্রিয়েটর, সাংবাদিক, ব্যবসা, পেশাজীবী ও অন্যান্য যাচাইকৃত প্রোফাইল। Approved category নিজের profile এবং public profile-এ দেখানো হয়।
- Settings-এ bKash, Nagad ও Rocket-এর প্রাপকের নম্বর সেট করার control যোগ হয়েছে। নম্বরগুলো signed-in app user পড়তে পারে; লেখা/পরিবর্তন custom-claim Admin-এর জন্য সীমাবদ্ধ। Website-এর বিদ্যমান settings/link fields অক্ষত।
- Verification application-এ wallet method বাছাই, admin-configured নম্বর কপি, প্রেরকের নম্বর, TrxID, NID ও নথি জমা দেওয়া যায়। এটি manual payment flow—কোনো স্বয়ংক্রিয় wallet API/transaction confirmation নয়; Admin-কে TrxID মিলিয়ে অনুমোদন করতে হবে।
- Admin verification queue-তে category badge, payment method, প্রাপকের/প্রেরকের নম্বর, TrxID এবং নিরাপদ image preview দেখানো হয়। Approve করলে request-এর validated category-ই user profile-এ লেখা হয়।
- `people_index` rule ও emulator test category mismatch/spoof ঠেকায়। নতুন RTDB rules source repo-তে আছে; live Firebase rules deploy করা হয়নি। Production-এ public category badge strict রাখতে rules deploy দরকার।
- সর্বশেষ যাচাই: Native App `pnpm run check` সফল, static Expo web export সফল, ১৯টি rules test file-এর ১০৮টি test পাস।


## Admin-only download ও maintenance settings

`app_download_url` control Admin Panel-এর Native App Runtime Control-এ রাখা হয়েছে; Native App-এর profile-card download button, share text ও QR payload থেকে এটি সরানো হয়েছে। Maintenance চালু/বন্ধ করার editable control কেবল Admin Panel-এ থাকবে। Native App-এ user-editable maintenance setting নেই; Admin চালু করলে ব্যবহারকারীরা notice পান বলে read-only maintenance listener/notice রাখা হয়েছে।
